# План реализации интерактивного 3D-стенда через платформу Vectary

> Решение проблемы огромной 3D-модели из Fusion 360

---

## 1. Проблема: огромная 3D-модель из Fusion 360

Ваша 3D-модель стенда из Fusion 360 слишком большая для прямой загрузки в веб. Это типичная проблема: CAD-модели содержат миллионы полигонов, сложную геометрию, множество мелких деталей (PLC, клеммники, датчики, провода), что делает их непригодными для интерактивного просмотра в браузере без оптимизации.

### 1.1. Рекомендации Vectary по размерам

| Параметр | Рекомендуемое значение | Почему важно |
|----------|----------------------|--------------|
| Количество полигонов | До 100 000 (100K) | Быстродействие в браузере |
| Количество объектов | До 100 объектов на сцене | Оптимальная загрузка |
| Размер файла (web) | До 5 МБ | Загрузка менее 3 секунд |
| Размер STEP/IGES импорта | До 50 МБ | Обработка без зависаний |
| Текстуры | До 100 текстур | Производительность |
| FPS в просмотрщике | Не менее 24 fps | Гладкое вращение |

## 2. Стратегия: разбить модель на части

Ключевая идея — **не загружать всю Fusion 360 модель целиком**. Вместо этого разбиваем на оптимизированные части.

### 2.1. Подготовка в Fusion 360 (до загрузки в Vectary)

#### Шаг 1: Упрощение геометрии в Fusion 360

- Удалите внутренние детали, которые не видны снаружи (внутренности PLC, плат, кабельных каналов)
- Упростите резьбовые соединения, мелкие фасонируемые элементы, скругления
- Объедините близкие компоненты в один mesh (например, группу клемм в один объект)
- Используйте **Mesh → Reduce** в Fusion 360 для снижения числа полигонов

#### Шаг 2: Экспорт по частям

Разделите стенд на логические группы и экспортируйте каждый отдельно в формат **OBJ** или **FBX**:

| Группа | Что входит | Примерный размер |
|--------|-----------|-----------------|
| Каркас стенда | DIN-рейки, корпус, дверцы, монтажная панель | Самая большая часть |
| PLC (контроллер) | Siemens S7-1200 или аналог, модульные блоки | Средний |
| HMI (дисплей) | Панельный дисплей, рамка, кнопки | Средний |
| Частотный преобразователь (VFD) | Частотный привод, радиатор | Средний |
| Клеммники | Все клеммные ряды (можно объединить в 2–3 группы) | Маленький |
| Датчики | Индуктивные, ёмкостные, оптические | Маленький |
| Кнопки и лампы | Все кнопки, переключатели, сигнальные лампы | Маленький |
| Автоматы и предохранители | Автоматические выключатели, УЗО | Маленький |
| Провода (упрощённые) | Основные кабель-каналы, жгуты | По желанию |

#### Шаг 3: Оптимизация текстур

- Текстуры **не более 1024×1024 px** для мелких компонентов
- Текстуры **2048×2048 px** только для крупных элементов (корпус, HMI экран)
- Используйте **JPEG** вместо PNG где возможно (меньше размер)
- Повторно используйте материалы: одинаковые материалы на разных объектах = 1 текстура

#### Шаг 4 (альтернатива): Используйте Vectary Processor

Vectary Processor — это десктопное приложение для конвертации CAD-файлов в оптимизированные mesh-модели. Оно позволяет:

- Конвертировать STEP/IGES в mesh с полным контролем качества
- Файлы никогда не покидают ваш компьютер (безопасность)
- Загрузка оптимизированной модели в Vectary одной кнопкой

> *Для получения доступа к Vectary Processor обратитесь по адресу: sales@vectary.com*

## 3. Сборка сцены в Vectary Studio

### 3.1. Создание проекта

1. Откройте **Vectary Studio** в браузере (vectary.com)
2. Создайте новый проект
3. Импортируйте первую группу (каркас стенда) через drag-and-drop (форматы: GLTF, GLB, OBJ, FBX, STL)
4. Поочерёдно добавляйте остальные группы, позиционируя их на свои места
5. Примените материалы из библиотеки Vectary (PBR-материалы для реализма)
6. Настройте освещение и HDRI-окружение

### 3.2. Проверка производительности

После сборки сцены нажмите **Preview** (в правом верхнем углу) и проверьте панели:

- **Objects** — количество объектов и полигонов
- **Textures** — количество и разрешение текстур
- **Loading time** — время загрузки (цель < 3 секунд)
- **Performance** — FPS (цель > 24 fps)

## 4. Реализация режимов (из ТЗ) через инструменты Vectary

### 4.1. Exploration Mode (Изучение компонентов)

**Инструменты Vectary:** Hotspots + Floating UI + Interactions

#### Как реализовать:

1. Добавьте **Hotspot** на каждый компонент (PLC, HMI, VFD, датчики, клеммники, кнопки, лампы, автоматы)
2. Для каждого хотспота создайте **Floating UI** (тип: **Docked** — боковая панель, чтобы не перекрывать модель, как требует ТЗ)
3. В Floating UI добавьте блоки:
   - **Text** — заголовок, назначение
   - **Image** — фото компонента
   - **Button** — ссылка на datasheet
4. Настройте **Interaction**:
   - **Trigger** = Click на hotspot
   - **Action** = Visibility (показать Floating UI) + Highlight (подсветка объекта) + затемнение остальных (через Materials action на полупрозрачный материал)

#### Структура карточки (по ТЗ):

| Блок карточки | Реализация в Vectary |
|---------------|---------------------|
| Блок 1 — Заголовок (название, тип, иконка) | Text element в Floating UI + Image element (иконка типа) |
| Блок 2 — Назначение (роль, подключение, сигнал) | Text element с 1–3 абзацами |
| Блок 3 — Технические параметры | Text element с форматированием или Container с несколькими Text |
| Блок 4 — Документация (PDF, руководство) | Button элементы с Link action (открытие в новой вкладке) |
| Большие компоненты (PLC/VFD/HMI) | Дополнительные Floating UI для схемы I/O, список каналов, кнопка «Теория» |

> *Важно: Vectary позволяет делать любой 3D-объект кликаемым, не только хотспоты. Можно сделать сам PLC кликаемым — через Triggers → Click на конкретный объект.*

---

### 4.2. Theory Mode (Теория)

**Инструменты Vectary:** Floating UI (Docked) + Interactions + Variants

#### Как реализовать:

1. Создайте набор **Floating UI** для каждого раздела теории:
   - Дискретные сигналы
   - Аналоговые сигналы
   - Питание
   - Общие провода
   - Экранирование
   - PLC архитектура
   - Защита от ошибок
2. Используйте **Container** элементы внутри Floating UI для структурированного текста
3. Добавьте **Image** элементы для упрощённых схем
4. Кнопка **«Показать на стенде»** = Interaction с Action:
   - Камера перемещается к нужному компоненту (**Look at** action)
   - **Highlight** на соответствующих элементах
5. Чеклист «перед подключением» = Container с Text элементами и иконками

#### Формат теоретической карточки (по ТЗ):

| Элемент | Реализация |
|---------|-----------|
| Краткое объяснение | Text element |
| Схема (упрощённая) | Image element (загрузить PNG/SVG схемы) |
| Связь с конкретным стендом | Button → Interaction: камера + подсветка |
| Список источников | Button с Link action (внешние ссылки) |
| Чеклист «перед подключением» | Container + Text + Image (иконки галочек) |

---

### 4.3. Guided Demo Mode (Анимации действий)

**Инструменты Vectary:** Animations (timeline) + Cameras + Interactions

#### Как реализовать:

1. Создайте **анимации** в режиме Animate:
   - Нажатие кнопки — сдвиг меша вниз и назад
   - Переключение тумблера — поворот
   - Касание HMI — подсветка экрана
   - Включение автомата — поворот рычага
2. Настройте **камерные позиции** (Set multiple cameras) для автоматического приближения к компоненту
3. Добавьте **Floating UI** с текстом инструкции внизу экрана («Шаг 1: нажмите...»)
4. **Interaction:** по нажатию «Далее» переключаются камера + анимация + текст инструкции
5. Для «руки/пальцев» — импортируйте упрощённую 3D-модель руки и анимируйте её движение к кнопке

#### Типы анимаций (по ТЗ):

| Тип анимации | Реализация в Vectary |
|-------------|---------------------|
| Нажатие кнопки | Timeline: Translation Y вниз → вверх (keyframe 0–30–60) |
| Переключение тумблера | Timeline: Rotation Z (keyframe с двумя позициями) |
| Касание HMI | Timeline: Material change (подсветка экрана) + появление UI |
| Включение автомата | Timeline: Rotation X (вкл/выкл позиция) |

> *Анимации в Vectary работают через timeline с ключевыми кадрами: start/stop для каждого объекта. Поддерживаются exploded view, сборка/разборка компонентов, плавные переходы.*

#### Поведение анимации (по ТЗ):

- Камера автоматически приближается → **Cameras action** (переключение на preset камеру)
- Объект подсвечивается → **Highlight action** (outline или color fill)
- Появляется «рука/пальцы» → **Visibility action** (показать 3D-модель руки)
- Действие повторяется 2–3 раза → **Animation action** с loop: true
- Текст снизу → **Floating UI** (позиция: bottom center)

### 4.4. Practice Mode (Практические работы) — MVP

**Инструменты Vectary:** Interactions (triggers + conditions) + Variables + Highlight + Floating UI

> *Это самая сложная часть проекта. Рекомендуется делать после всех остальных режимов.*

#### Как реализовать базовый уровень:

1. Каждая клемма/точка подключения = **отдельный кликаемый объект** в Vectary
2. Используйте **Variables** в Vectary для отслеживания состояния:
   - `current_step` (номер текущего шага)
   - `connection_1_done` (true/false)
   - `connection_2_done` (true/false)
   - `all_connected` (true/false)
3. **Highlight action** для цветовой индикации:
   - Серый — неактивно
   - Жёлтый — следующий шаг
   - Зелёный — выполнено
   - Красный — запрещено
4. **Conditions** в Interactions: проверить, что студент нажал на правильную клемму
   - Если да → переход к следующему шагу (Set Variable)
   - Если нет → сброс (Set Variable → начало)
5. **Floating UI** показывает текущий шаг, инструкции, прогресс

#### Архитектура практики (по ТЗ):

```
Practice_ID: P001
Название: Подключение кнопки и лампы
Цель: Научиться подключать дискретный вход/выход PLC

Шаг 1 → Шаг 2 → Шаг 3 → Шаг 4 → Финальное состояние

Шаг 1: Подключить провод от кнопки к клемме входа %I0.0.0
Шаг 2: Подключить общий провод кнопки к 0V
Шаг 3: Подключить провод от клеммы выхода %Q0.0.8 к лампе
Шаг 4: Подключить общий провод лампы к 0V
Финал: Кнопка и лампа подключены → можно включить питание
```

#### Логика пошагового выполнения в Vectary:

| Элемент | Interaction в Vectary |
|---------|----------------------|
| Текст инструкции | Floating UI → Text (меняется через Visibility по Variable) |
| Подсветка нужных элементов | Highlight action (жёлтый) при `current_step == N` |
| Визуальное соединение (провод) | Visibility action: показать заранее созданный 3D-провод |
| Кнопка «Далее» | Скрыта; переход происходит по клику на правильную клемму |
| Студент не может перескочить шаг | Condition: `current_step == N` перед каждым действием |
| Ошибка → начало заново | Condition: если клик на неправильную клемму → Set Variable `current_step = 0` |

> *Для полной реализации логики «правильных соединений» с множеством практик может потребоваться Vectary API для связи с внешней логикой на web-странице (Business план).*

### 4.5. Переключение режимов

Реализуется через **верхнее меню** на базе Floating UI:

- Создайте Floating UI с 4 кнопками (Exploration, Practice, Theory, Guided Demo) в верхней части экрана
- Каждая кнопка = Interaction:
  - **Скрыть** все Floating UI других режимов (Visibility action: Hide)
  - **Показать** UI текущего режима (Visibility action: Show)
- Используйте **Variable** для хранения активного режима (`active_mode = "exploration"`)
- Кнопка **«Назад»** = та же логика: скрытие карточки, возврат к меню режима
- Всё **без перезагрузки сцены** (Vectary работает внутри одного iframe)

## 5. Система состояний компонентов

Для реализации состояний (OFF, ON, ERROR, HIGHLIGHTED, LOCKED) используйте комбинацию инструментов Vectary:

| Состояние | Реализация в Vectary | Пример |
|-----------|---------------------|--------|
| OFF | Базовый материал (тёмный/серый) | Лампа не светится |
| ON | Materials action: замена на светящийся/яркий материал | Лампа жёлтая/зелёная |
| ERROR | Highlight action (красный outline) + анимация мигания | PLC с красной индикацией |
| HIGHLIGHTED | Highlight action (glow/outline) + затемнение остальных | Выбранный компонент |
| LOCKED | Полупрозрачный материал + отключение кликов (Interaction Conditions) | Нельзя взаимодействовать |

## 6. Механизмы безопасности (из ТЗ)

| Требование ТЗ | Реализация в Vectary |
|---------------|---------------------|
| Не позволять соединять произвольные клеммы | Conditions в Interactions: проверка совместимости через Variables |
| Не позволять включать питание до завершения подключения | Variable `all_connected = true` как Condition для кнопки питания |
| Предупреждение при неправильном действии | Floating UI с красным фоном и текстом ошибки (Visibility по Condition) |
| Обязательный Safety Screen | Отдельный Floating UI с информацией о безопасности перед началом практики |

## 7. Архитектура решения

### 7.1. Вариант А: Чистый Vectary (без кода)

Вся логика реализуется внутри Vectary Studio через Interactions / Floating UI / Variables. Embed через iframe на ваш сайт.

| Плюсы | Минусы |
|-------|--------|
| Нет необходимости в программировании | Сложная логика Practice Mode может быть громоздкой |
| Всё в одном месте | Ограниченные возможности валидации ответов |
| Быстрая итерация дизайна | Трудно масштабировать (много практик = много Interactions) |
| Работает на любом устройстве | Необходим план Pro или Business для embed |

### 7.2. Вариант Б: Vectary + API + Внешний веб-сайт

3D-сцена в Vectary, логика Practice Mode на вашем сервере. Связь через **Vectary Model API** (Events & Listeners).

| Плюсы | Минусы |
|-------|--------|
| Полный контроль над логикой практик | Требует web-разработчика |
| Можно сохранять прогресс студента | Сложная интеграция |
| Легко добавлять новые практики | Дороже в разработке |
| UI за пределами iframe (больше гибкости) | Два места для поддержки (Vectary + сайт) |

#### Как работает API-связь:

```javascript
// Пример: подписка на событие клика по клемме в Vectary
viewer.addEventListener("mouse_click", (result) => {
  const clickedObject = result.objectName;
  
  // Проверяем, правильная ли клемма
  if (clickedObject === expectedTerminal) {
    // Переходим к следующему шагу
    viewer.sendEvent("next_step", currentStep + 1);
  } else {
    // Сброс практики
    viewer.sendEvent("reset_practice");
  }
});

// Отправка данных в Vectary для подсветки
viewer.sendEvent("highlight_terminal", "terminal_I0.0.0");
```

> **Рекомендация:** начните с Варианта А для Exploration, Theory и Guided Demo. Добавьте Вариант Б позже для сложных практик.

## 10. Резюме

### Почему Vectary — хороший выбор для вашего ТЗ:

- **Работа в браузере** — не нужно устанавливать программы студентам
- **No-code** — большую часть логики можно сделать без программирования
- **Интерактивность** — хотспоты, анимации, Floating UI, Variables — всё что нужно для ТЗ
- **Оптимизация больших моделей** — Simplify tool, Vectary Processor, разделение по частям
- **Embed одним iframe** — легко вставить в любой сайт (Wix, Webflow, самодельный)
- **AR поддержка** — студентам можно посмотреть стенд через телефон в дополненной реальности
- **API для сложной логики** — когда no-code не хватает, есть Model API для Practice Mode

### Ограничения Vectary (что нужно учитывать):

- Не поддерживает импорт Fusion 360 (.f3d) напрямую — нужна конвертация в OBJ/FBX/STEP
- Сложная логика валидации (Practice Mode) может требовать API (Business план)
